# P1AL — Private one-owner real-compatible Google metadata consent controller

**Status:** Unmounted PRIVATE source-only candidate. This is not an applied Google grant, not a real Google request, not public OAuth ingress and not financial content ingestion. Owner approved using the existing single-folder Drive client after G2. The public Railway callback is registered with Google but has NOT been activated by this code.

## Source implementation

- `backend/app/private_owner_real_google_http.py` is a separately instantiated FastAPI factory (never imported/mounted by the live `app.preview_api` or `app.private_runtime_entrypoint`). It adds exact `POST /internal/drive/oauth/start`, `GET /internal/drive/oauth/callback`, `GET /internal/drive/oauth/status` to the established one-owner MFA app.
- **Start:** strict same-origin owner POST with no body, private gateway proof, live MFA session and CSRF via P1Q/P1R; P1R encrypts one-use PKCE state and commits before any provider redirect. Authorization URL requests the exact `drive.metadata.readonly` scope and the registered Railway callback; never file.readonly, media or write scope.
- **Callback:** only exact unique state+code query, verified SameSite=Lax owner cookie and same private gateway; P1R atomically claims/erases state *before* any Google HTTPS exchange. P1C accepts only a fixed TLS no-redirect token endpoint and verifies the approved owner-owned, private/unshared, untrashed folder. P1M stores the refresh token as authenticated Postgres ciphertext, owner/client/folder/metadata-scope bound with explicit revision/HMAC. **Any failure** generates only identical no-store/no-referrer 303 to `/owner-login`, no raw code, state, verifier, token, folder ID or provider error in response/log. No provider retries with a spent code.
- **Status:** the authenticated owner can learn only whether an accepted private encrypted metadata refresh grant exists, never its value or a file's contents. Real metadata sync heartbeat remains null until implemented and actually run.
- Existing P1C network adapter also accepts a **separately gated** private cloud metadata flow behind explicit P1AL+P1R+P1M/G2 review flags. Local legacy SQLite OAuth tests remain unchanged, and the code does not relax the default-deny Google network setting.
- Synthetic adversarial test suite injects a fictional Google transport: exact metadata scope, OAuth code exchange + one-folder proof + encrypted refresh grant with owner HMAC, replay denial, duplicate parameters/missing cookie/host spoof/CSRF denial, fixed redirect/no leak. No real Google network, owner account, folder names or client secret in CI.

Do not claim Google provides native folder-only scope. Restricted `drive.metadata.readonly` scope itself cannot read file content.
