## Delivery order and milestone exit criteria

### 1. Google Drive → Personal CFO — start immediately (#98)
**A. Safe now, owner-independent:** extend the existing fictional one-folder Drive metadata planner to a durable, transactionally indexed synthetic **document inbox** with encrypted metadata, HMAC-only source identities, complete-snapshot/rollback safety, source revision changes, idempotent scan replay, duplicate candidates, disappeared/access-lost signals and a bounded review/follow-up queue. Test in ephemeral PostgreSQL18 and no-op replays; return only privacy-safe aggregate status to a synthetic dashboard. The one-folder scope is fixed by private configuration, not compiled into public source code. Originals must not move/rename/delete.

**B. Requires account/private security acceptance:** Personal CFO app-side Google OAuth and credential rotation; owner-approved folder-only query enforcement even if the Google account grants a broader read permission; reliable real sync/cursor/locking, retry/backoff, and a private source index. The connected ChatGPT Google Drive plugin is **not** application OAuth. The optional owner-owned hourly Apps Script in PR #97 is not installed. A Google Drive watch/metadata check must not claim that originals have been imported. Future uploads in the same folder must be discovered without repeatedly asking the user to share each file.

**C. Exit:** initial + future uploads appear once in the *app's* verified index with clear stages, virtual categories and a privacy-safe review queue; revisions and duplicates cannot overwrite certified evidence; inaccessible files flag follow-up; no financial claim until G2/G3 gate.

### 2. Genuine document understanding — G3 (#29, #30)
**Exit:** independently reviewed private isolated worker and encrypted original vault; approved secure temporary password unlock; format-versioned real bank/FBR/accountant adapters; authentic page/row/cell provenance, opening/running/closing balances, overlap/reversal handling and official filed-vs-draft FBR evidence. Unknown/unsafe files stay quarantined, not inferred.

### 3. Encrypted authoritative ledger — G1 (#21)
**Exit:** source-complete owner×account×tax-year records for all bank/cash/loans/investments/assets/FBR claims; no double-counted transfers or realized-vs-unrealized claims; immutable correction audit, encrypted backups/independent restore with failure injection; reviewed real application authority switch with complete rollback; **only after** independent sign-off, retire plaintext active legacy records. No new financial totals from unverified owner proposals.

### 4. Owner production security — G2 (#28, #3)
**Exit:** owner-enrolled MFA + recovery verified across devices/workers and rate-control adversarial tests; private TLS/host/origin/CSRF/role and session protections; encrypted Drive OAuth credential custody and original vault; independently tested offsite backup and restore. The owner must approve exact private resource scope, any live Railway secret/role changes and rollback plan. **Hard prerequisite to any genuine raw financial document processing regardless of rank.**

### 5. Tax and accountant reconciliation — G4 (#5, #30)
**Exit:** year-specific official law and evidence linked to filed return acknowledgments, clear DRAFT vs filed distinction, historical bank/wealth/tax account continuity, withholding source links, explanations/questions and adviser-reviewed lawful planning. Do not guess amounts or official statuses.

### 6. Mobile-first PWA and real financial pulse — G5 (#99, #25)
**Exit:** tested installability/phone-first navigation and private authenticated cache policy; verified source-backed monthly spending trends, recurring bills and upcoming payment dates, investment expected returns with uncertainty, loan obligations, file coverage and actionable follow-ups. User-friendly terms and financial data freshness/provenance; no fictional/unknown amounts displayed as real balances.

## Operational rules for all six

- **One inbox.** The user uploads old/future documents into their existing private Google Drive folder. Personal CFO performs *virtual* organization, not physical reshuffling. Keep private Google folder ID, original filenames/IDs, account info, PDF passwords and original files OUT of public GitHub/Actions, logs and synthetic Railway preview.
- **Evidence-first.** A filename is only an untrusted type hint; a Drive MD5 is only a duplicate **candidate**; a bank credit is not automatically income; an asset valuation is not realized return; an accountant draft or filename “FINAL” is not proof of an official FBR filing.
- **Security cross-cutting.** G1/G2/G3 must independently accept genuine source access before enabling `APP_DATA_MODE=real`. No genuine data uploads to CI, no live finance cutover, no unrelated connector/provider or new paid resources without owner approval. Synthetic tests can progress in any lane in parallel.
- **Cost:** Google Drive is the selected document store. Backblaze B2 deferred. The optional metadata watch may run without another server, but actual private original parsing must be securely hosted/accepted before processing.
- **Hand-off and traceability:** Each PR references its numbered priority and GitHub issue, runs exact-head CI and updates `docs/CURRENT_HANDOFF.md`, `docs/PROJECT_STATUS.md`, `AGENT_START_HERE.md` and relevant issues. This roadmap retains order until owner explicitly reprioritizes it.

**Next implementation after this roadmap lands: #98, Priority 1A — transactionally durable synthetic Drive metadata inventory and privacy-safe document-review queue.**
