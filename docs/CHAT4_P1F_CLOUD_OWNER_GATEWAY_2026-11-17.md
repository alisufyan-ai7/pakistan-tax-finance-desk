The private service still runs `app.preview_api:app`; **do not mount this candidate there**. The exact Google authorized redirect `https://personal-cfo-frontend-preview-development.up.railway.app/api/drive/oauth/callback` was registered by the owner but **is not served**.
- Candidate module `backend/app/drive_cloud_owner_gateway.py` provides a **separately constructed**, non-autoloaded, synthetic-only FastAPI app factory with only `/internal/drive/oauth/start` (POST), `/internal/drive/oauth/callback` (GET), `/internal/drive/oauth/status` (GET), `/internal/drive/oauth/disconnect` (POST), and `/internal/drive/auth/logout` (POST). There is **no public password login endpoint**, no OAuth token exchange, no real Google call, no real file listings and no financial data mutation.
- The fake gateway is doubly gated by `P1F_SYNTHETIC_OWNER_GATEWAY_ONLY=1` + the P1E/P1D/P1B synthetic/fake-client+folder contracts, with SQLite allowed only in disposable tests. It refuses authentic client/folder/token formats even if the guard flags were set accidentally. No Railway variables/configuration are changed or needed for current tests.
- A test-only helper verifies a fictional scrypt password + RFC6238 TOTP, atomically consumes the monotonic TOTP counter, stores **only a hashed** 15-minute session and hashed CSRF token in existing synthetic owner-session tables. Session cookie is host-only `__Host-cfo-drive-owner`, `Secure; HttpOnly; Path=/; SameSite=Lax`. **Lax, not Strict, is necessary for Google's top-level cross-site GET callback**. On unsafe POSTs, exact `Origin` and valid session-specific `X-CSRF-Token` are mandatory. There is no public helper/login route and consequently no internet-facing password attempt surface or claim of a complete distributed login throttle. Failed authentication cannot create a session; reused TOTP counters cannot mint a second session.
- Only the exact HTTPS Railway origin/host passes. The isolated candidate rejects HTTP, alternate Host/port, spoofable `X-Forwarded-Host/Proto`, arbitrary public/private endpoints, unexpected callback query parameters, duplicate state and non-fictional OAuth codes. Its callback accepts **only synthetically prefixed fake codes**. The corresponding single-use OAuth state is encrypted and HMAC-indexed by P1E, **bound to the exact browser session digest** and atomically consumed on the correct callback. A wrong-cookie callback cannot claim or consume another session's state. No actual token, authorization URL or sensitive cookie is returned to JavaScript.

## Explicit remaining security and deployment blockers

1. **Owner authentication is not production ready.** The helper is used only by synthetic tests, not by a browser-accessible authentication service. Secure owner provisioning/login, cross-worker rate limiting, account recovery, session rotation/device revocation, security audit trails, trusted-proxy scheme/host resolution and real credential custody require a separate G2-reviewed implementation.
2. **OAuth public callback is not enabled.** The public frontend's current Nginx config must not be edited to forward `/api/drive/oauth/*` before an independent review confirms exact five path/method mappings, safe URL/query handling (authorization codes must not enter access logs), trusted TLS-forwarding, cookies, CSRF state/session binding, DB role isolation and disaster recovery. No generic `/api/*` proxy or direct public private API.
3. **Real Google and live Railway are unchanged.** The existing OAuth client, redirect registration, metadata scope, client secret and private folder remain as configured by the owner, with no actual Google consent, token storage, Google API call, scheduled scanner or original-byte permissions. No secrets, original files, document titles or owner identity are committed.
4. **Google scopes:** `drive.metadata.readonly` can disclose metadata across the account in the OAuth consent scope; application code must restrict queries to the approved owner-private folder and verify owner identity and folder integrity. A Google External/Testing refresh token may expire after seven days. This requires lifecycle planning before claims of continuous syncing.
5. **No owner action required for this code-only milestone.** Actual credential provisioning, opening a route to public traffic, changing an existing Railway database role/variable/deployment or initiating Google authorization needs explicit scoped approval and independent security acceptance. Keep `APP_DATA_MODE=real` and all G1/G2/G3 actual-data release gates blocked.
