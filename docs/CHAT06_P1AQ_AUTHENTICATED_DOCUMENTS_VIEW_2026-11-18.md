# Chat06 P1AQ — Authenticated mobile Documents shell for merged bounded P1AP snapshot

**Not a live Google consent:** This is an owner-only source integration. [Merged P1AP #172](https://github.com/alisufyan-ai7/pakistan-tax-finance-desk/pull/172) is the authoritative all-or-nothing, up-to-1000-file one-folder-only metadata snapshot engine. This slice does **not** duplicate Google list pagination, persist source files, or return raw Drive IDs.

The private P1AL controller adds one default-off `POST /internal/drive/metadata/refresh`. P1Q requires exact trusted gateway/Host/origin and authenticated 15-minute owner session+CSRF; the HTTP controller refuses bodies/queries and delegates only to #172's `scan_one_owner_folder_metadata`. That function independently gates metadata-only real Google network, encrypted P1M grant, exact one pinned private owner-owned folder, bounded pages with no duplicates/partial searches/foreign parents, and redacts raw IDs, refresh tokens and file bytes. Only sanitized display name, virtual collection, review status, date and size reach the private owner JSON, with explicit false flags for finance evidence/source import/durable sync.

The existing public Nginx gains only a corresponding exact `POST /api/drive/metadata/refresh`, disabled unless the distinct G2 owner and Google ingress switches are approved and a server-side gateway token is configured. It rejects queries, uses fixed private host/proxy header sanitation/no-access-log and global rate limit. No `/api/*` wildcard, uploaded originals, public financial API or provider token/media download.

The mobile owner-login page, after actual authenticated Google consent, loads a complete one-folder metadata snapshot on demand and displays filename/category/date using DOM `textContent` only. A Refresh button rechecks the folder; no localStorage, cookie JS, HTML parsing of filenames, or persistent data store. This is a useful starting view **not** a continuous background scanner or finalized accountant/ledger review queue.

Strict release boundary: Actual Personal CFO Google consent has NOT been activated by source merges. Existing keys/one-owner MFA/P1R/P1M credential custody, exact Railway platform TLS/log and public edge acceptance, operator-generated gateway proof, explicitly reviewed flags and one owner browser consent are still required. Original FBR/bank bytes and real financial mode await G1/G3. Do not require repeated backup-copy/restore exercises to run these synthetic tests; the owner already confirms encrypted copies in two places, while real credential restore acceptance remains unverified.
