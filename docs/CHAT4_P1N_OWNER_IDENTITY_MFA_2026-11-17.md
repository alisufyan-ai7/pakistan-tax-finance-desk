# P1N · Private owner MFA/session core — source-only security milestone

**17 November 2026 · Issue #126 / parent #110 · Current main baseline #125.**

The owner approved real Google OAuth preparation and verified the existing exact Google Railway callback and account test-user/folder ownership. The only real Google client secret was **sealed and STAGED** on the approved private Railway service; leave it unapplied.

This independent branch introduces **real-compatible, owner-specific MFA and session primitives**, distinctly separate from the old `synthetic-owner` test login. `backend/app/private_owner_identity.py` plus additive `0019_private_owner_auth` migration store a singleton HMAC owner reference, scrypt password verifier, separately keyed AES-256-GCM TOTP seed envelope, HMAC-authenticated row/revision, single-use last TOTP counter, durable five-failures/15-minute lockout, and separate HMAC-minted 15-minute owner session/CSRF records. Transactional PostgreSQL advisory lock serializes first enrollment, attempts, TOTP replay, lockout and session creation across workers. There is no plaintext password/TOTP/session in SQL, no stored fake/real personal owner email, no public route and no login service mounted. The caller must arrange an independently authenticated offline enrollment path; a true value for `verified_offline_bootstrap` is **not proof of operational G2** by itself.

The module requires **default-OFF** `P1N_PRIVATE_OWNER_AUTH_ONLY` and `P1N_G2_OWNER_IDENTITY_REVIEWED`, independent 32-byte owner encryption/identity/session HMAC keys, private PostgreSQL and `APP_DATA_MODE=synthetic`. Only disposable tests use `P1N_SQLITE_FAKE_TEST_ONLY`. Real original finance mode remains hard-blocked; the module never reads `P1C_GOOGLE_CLIENT_SECRET`, a Google token, a bank record or FBR document.

**Recovery deliberately fails CLOSED.** Owner lost-device MFA reset / recovery codes are *not yet implemented* in this real-compatible service; existing `persisted_owner_recovery` remains synthetic-only and cannot be silently borrowed. `inspect_private_recovery_availability()` explicitly reports the unsatisfied recovery gate. Until independently reviewed recovery enrollment/atomic redemption, key custody/restore and a private UI, real owner enrollment and OAuth consent may NOT be activated.

New independent tests use only fictional owner ID/password/TOTP, validate wrong password and tamper, duplicate owner, concurrent replay, lockout, cookie revocation, expiry, CSRF, private no-route and negative `APP_DATA_MODE=real`. Disposable PG18 CI must additionally verify first-session race and lack of private plaintext in SQL. Additive schema `owner_private_identities` and `owner_private_sessions` is covered by G1 complete source census, backup/clone checks and exact `0019_private_owner_auth` Alembic revision; it is NOT an authorization to apply a migration to Railway live PostgreSQL.
