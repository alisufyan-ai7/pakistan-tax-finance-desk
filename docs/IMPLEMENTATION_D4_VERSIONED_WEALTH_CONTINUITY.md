# D4 — synthetic source-versioned wealth continuity review

This is a **partial G4/accountant domain** slice under the [Owner MVP completion blueprint](OWNER_MVP_COMPLETION_BLUEPRINT_2026-11-16.md), [FBR tax #5](https://github.com/alisufyan-ai7/pakistan-tax-finance-desk/issues/5) and [accountant workflow #30](https://github.com/alisufyan-ai7/pakistan-tax-finance-desk/issues/30).

`backend/app/wealth_version_review.py` models immutable synthetic wealth sources tagged DRAFT, FILED_ORIGINAL or FILED_REVISION and explicit revision chain/acknowledgement fixture claims. Before comparing a tax-year boundary, it rejects missing/duplicate/ambiguous/contradictory version ancestry and keeps individual/company/AOP financial ownership separated. For the previous tax year, only latest *fixture-asserted independently acknowledged FILED* source may provide prior closing wealth; an unverified filing label is not proof. For current year, prefer latest fixture-acknowledged filed version when present; otherwise use latest DRAFT as provisional, never promote it to FILED. July–June TY boundary is explicit. Any mismatch is a `REVIEW_REQUIRED` question, **not a claim that an earlier FBR return was wrong**. Missing opening/closing evidence yields `difference_minor=null` (not zero); exact integer minor units only.

**CRITICAL BOUNDARY:** `acknowledgement_verified_in_fixture=True` is only a **synthetic test assertion**, NOT a genuine IRIS verification or a reusable authentication credential. The resulting receipt always sets `filing_acknowledgement_verified_by_application=False`, `wealth_reconciled_to_bank_cash_assets=False`, `fbr_ready=False`, `tax_due_minor=None`. There is no upload endpoint or financial-source persistence, and `APP_DATA_MODE=real` is rejected. This code is not an official FBR tax statute calculation; year-specific law, actual verified filing acknowledgement, complete source-driven bank/cash/asset reconciliation and accountant export remain later gates.

Tests cover draft-vs-filed matching and discrepant cases, latest authenticated *fictional* revision ancestry, missing/unverified evidence, legal-person isolation, duplicate originals, invalid revisions, invalid values and real-data fail-closed. Only fabricated fixtures and GitHub Actions, no Docker/new cloud/private records.
