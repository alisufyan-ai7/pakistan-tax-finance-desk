# Railway private PostgreSQL preview API — synthetic-only

The owner authorized connecting the Personal CFO public **synthetic preview** to a separately secured backend and Postgres in the existing `personal-cfo-dev-sandbox` Railway `development` environment on 2026-11-16. This work does not authorize real-owner records, importing banks, or filing FBR returns.

**Backend entrypoint**: `backend/app/preview_api.py:app` (NOT the large `backend/app/main.py` legacy local finance app). One read-only `/healthz` and one private synthetic `/internal/preview/status` (GET-only). The API only runs with `APP_DATA_MODE=synthetic`, `PERSONAL_CFO_PRIVATE_PREVIEW=enabled`, a long independent `PREVIEW_INTERNAL_TOKEN` (in Railway environment variables, never GitHub), and `DATABASE_URL` pointing to `*.railway.internal:5432` PostgreSQL, with TLS required. SQLAlchemy uses a bounded 2-connection pool and read-only PostgreSQL transactions. No app-side migrations, files, account balances, financial SQL or external API actions.

- **Private service only** — NO public Railway domain and NO TCP proxy. Public frontend Nginx may proxy only one **exact** GET `/api/preview/status` path with a server-side authentication token to `/internal/preview/status` over Railway's **project-private DNS**. There is no browser-side key.
- Internal status returns only verified DB connectivity and the previously tested `owner_workspace_status_v1` data, with every genuine economic field `null`, `real_data_authorized=false`, G1–G5 release gates false and canonical schema `NOT_CERTIFIED`. The DB is empty of real records and the connectivity check is `SELECT 1`. A reachable database is not a canonical financial migration.
- Tokens are manually provisioned into **two services' secret environment values** by the authorized deployment agent and are never printed in source code, logs or website. The frontend Nginx config is generated at runtime from an environment template filtered to that one variable. The public dashboard remains fictional. Unauthorized internal calls fail 401; unsupported tax years fail 422; unrecognized paths fail 404.
- **Postgres**: Railway-maintained PostgreSQL 18 SSL template, persistent private volume and generated Railway database password. No public TCP proxy; no real bank data. DB backups, PITR, DB role least privilege and key/offsite recovery are future acceptance gates.
- **CI**: unit hostile path/token/real-mode/URL/readonly tests in backend pytest + existing PostgreSQL18 Actions, without uploading real data. Deploy only verified `main` to the already approved project, and inspect Railway deployment status, no public domain, and public synthetic exact-route behavior.

**Boundaries:** G1 active financial encryption/cutover still incomplete (legacy ledger has plaintext and must NEVER deploy publicly); G2 production MFA/recovery and audit still incomplete; G3 actual banking/FBR documents and G4 FBR law review incomplete. **No real money, data or personal records in Railway**. A private network plus TLS and a token does not make the broader financial system production-ready.
