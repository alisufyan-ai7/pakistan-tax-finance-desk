# P1AP — Mobile owner-only one-folder live metadata review

**Status:** source implementation, requires the separately accepted private owner MFA and real metadata-only Google connection before any endpoint can be used. No original PDF/XLSX bytes or FBR data are imported, parsed or sent to the public preview. This is **on-demand live metadata pagination**, not a persistent background synchronization scheduler or an accountant-certified financial evidence queue.

## Implementation

- Adds only `POST /internal/drive/metadata/page` and exact gated browser `POST /api/drive/metadata/page` with no query string, up to 2 KiB request, protected by the existing P1AK/P1AO **default-off** ingress flags, private gateway proof, exact Host/method, no sensitive Nginx access/error request-target logs and bounded global rate. The private FastAPI handler also requires live one-owner MFA session and rotated CSRF under P1Q, P1AL real-compatible Google metadata-only authorization, isolated P1M encrypted refresh-token grant and trusted P1C HTTPS transport. No unrelated paths mounted by the preview.
- Client requests a page via JSON body `{"page_token":null}` (subsequently an opaque max-1024-char token); **no pagination token, document name or Google authorization code in URL**. The backend obtains an access token by refreshing its encrypted private grant in memory, re-verifies the approved private/unshared/owner-owned Drive folder, and calls P1C's fixed one-folder direct-child metadata-only `files.list` with bounded page size 100. No media download, file bytes, Google Drive-wide search, file mutation or finance ledger insertion. Rotated provider refresh token, when supplied, is immediately re-encrypted under the owner's existing P1M custody.
- Strict metadata response whitelist `id`, `name`, MIME, modified-time and numeric size only; all other provider fields discarded. Response no-store and behind owner session. UI renders filenames strictly with `textContent`, never HTML or localStorage; supports Refresh and Load more, makes no bank classification claims, clearly says no source bytes imported. It is displayed only after app actually reports a connected verified grant.
- Synthetic fake Google provider and existing PG18 CI must prove CSRF/origin/JSON duplicate denial, refresh token never exposed, one-folder-only query/parent validation, no `alt=media`, no persisted filename or financial source fact and deterministic secure mobile list.

## Remaining before user can actually see private documents

G2 exact owner/private ingress and platform logging/cookie acceptance, owner-only gateway key preparation (P1AM), existing reviewed P1R/P1M distinct key custody, true P1AL/AN OAuth code exchange under the already registered HTTPS callback, and one actual owner-performed Google consent. The previously staged sealed Google secret must not be blindly applied along with unrelated pending Railway changes. Only after those gates should `P1AO_GOOGLE_INGRESS_ENABLED` and backend P1AN switches be deliberately enabled.

**Future:** reliable background scan lease, encrypted persistent review classifications/dedup and source coverage, linked accountant working papers and finance evidence require further P1/G1/G3 work; this live view is a safe initial owner utility rather than final sync. No repeat owner's encrypted backup-copy or Docker restore exercises are required merely to build this source code; the actual independent credential restore is a separately recorded release gate.
