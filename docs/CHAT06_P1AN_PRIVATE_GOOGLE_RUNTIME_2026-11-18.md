# P1AN — Explicitly gated existing Railway private owner/Google runtime integration

**Scope:** source-only. Existing `backend/Dockerfile.preview` uses `app.private_runtime_entrypoint:app` with default-off G2 sign-in. P1AN extends ONLY the approved **private** owner runtime, never the public frontend or financial ledger. No Railway flag/secret, real token, Google consent or original document is changed here.

When `P1AJ_OWNER_LOGIN_RUNTIME` is absent/disabled, the app still exposes only the same read-only synthetic preview API. When the separate P1AJ owner login is enabled without `P1AN_GOOGLE_METADATA_RUNTIME=1`, it still exposes exactly three internal MFA routes and refuses an unbound `P1C_GOOGLE_NETWORK_ENABLED=1`.

Google metadata routes are added ONLY when the operator independently accepts `P1AN_GOOGLE_METADATA_RUNTIME=1`, `P1AN_G2_GOOGLE_CALLBACK_INGRESS_REVIEWED=1`, `P1AN_METADATA_ONLY_HTTP_ACCEPTED=1` **and** all existing P1AL/P1R/P1M/P1C/P1N/P1Q/P1AI/G2 key, one-owner, restricted TLS role, callback and private gateway flags are separately accepted. The entrypoint then instantiates the real-compatible P1AL controller behind P1AI's one-owner restricted SQL/recovery lifespan. Exact added private routes: `POST /internal/drive/oauth/start`, `GET /internal/drive/oauth/callback`, `GET /internal/drive/oauth/status`; no finance, content/media, Drive-wide search, setup/recovery or wildcard API. Public OAuth routes remain absent from the live Nginx in this PR.

Source CI exercises absent/rejected flags, mandatory independent Google security conditions, exact private routing and no public alias. Existing default-on preview and three-route owner-only tests remain green. The actual Railway provider-secret value remains staged/unapplied; no real Google network calls in CI, and no actual provider grant until owner login and personally attended browser consent.
